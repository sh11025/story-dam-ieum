### 추가/변경
- 시험 방법: 작업 공간은 채용 사이트 접속이 막혀 있고(`network` 실패), 이 연결 방식으로는 사용자 PC에서 `npm run check:job`을 직접 실행할 수 없다. 그래서 **사용자 PC의 Claude 앱 안 브라우저로 공고 페이지 원본(HTML)을 받아** 작업 공간으로 옮긴 뒤, 같은 공고 읽기 코드(`extractJobPage`)로 시험했다. 원본은 광고·스크립트만 빼고 크기를 줄였다(JSON-LD·Next.js 데이터·숨김 표시는 유지).
- **사이트별 본문 창 읽기**(`server/jobPage.ts` `detailPageUrl`, `importJobPage`): 사람인은 공고 본문이 `/zf_user/jobs/relay/view-detail?rec_idx=…`, 잡코리아는 `/Recruit/GI_Read_Comt_Ifrm?Gno=…` 안쪽 창에 따로 있다. 서버가 그 창도 받아(8초 제한, 실패해도 원래 페이지 결과는 보여 줌) 본문으로 쓴다. `/api/job-posting`과 `check:job`이 이 함수를 쓰도록 바꿨다.
- **숨긴 글 제거**: 사람인 본문 창 안의 검색엔진용 직무 분류 목록(`display:none` 등)을 지운다. `border-width:0px` 같은 테두리 설정은 숨김으로 보지 않는다.
- **표로 된 공고 읽기**(`fieldsFromTables`): 가로 표 "모집부문 | 담당업무 | … | 응시자격"은 칸별로 모으고 부문 이름을 `[영업팀]`처럼 앞에 붙인다. 자격 칸의 "… 우대" 줄은 우대사항으로 옮긴다. 세로 표 "담당업무 | 내용"도 읽는다. 표 값은 글에서 못 찾은 항목에만 쓴다. 항목 이름에 `응시자격` 추가, 표 칸 이름 비교용 `fieldKeyOfLabel`(띄어쓰기 무시, 예: "응 시 자 격") 추가.
- **다른 구역 제목에서 멈춤**: 전형절차·접수방법·근무조건·복리후생 등이 나오면 앞 항목 목록을 끝낸다(잡코리아 우대사항에 "전형절차"가 섞이던 문제).
- **마감일**: 공고 요약의 "마감일 : 상시채용"이면 JSON-LD의 날짜(1년 뒤로 채워진 값)를 쓰지 않는다.
- **그림 공고 안내**: 본문 창에 그림만 있고 글이 거의 없으면 "공고 내용이 그림(이미지)으로 올라와 있어 글자를 읽을 수 없어요…"라고 정확히 안내한다.
- 시험용 페이지 8개를 `tests/fixtures/job-pages/`에 줄여 저장하고 서버 테스트 5개(사람인·원티드·잡코리아·세로 표·숨김 규칙)를 추가했다.

### 오류 · 원인 · 해결
1. **사람인·잡코리아에서 항목을 거의 못 찾음** — 개발자용: 공고 본문이 iframe(다른 창)에 있어 첫 페이지 HTML에는 메뉴와 요약만 있었다. 일반인용: 공고 내용이 페이지 속 작은 창에 따로 들어 있어 겉 페이지만 읽고 있었다. 해결: 본문 창 주소를 만들어 함께 받아 옴.
2. **원티드 자격요건이 "경력"** — JSON-LD의 `experienceRequirements` 분류 이름을 내용으로 씀. 해결: 20자 미만 분류 이름은 빼고, 페이지 데이터(Next.js)의 자격요건·우대사항을 함께 봄.
3. **사람인 표 공고(55258367)에서 업무·자격 0개** — 표를 글로 펼치면 칸 이름과 값이 떨어져 줄 단위 규칙으로는 못 찾음. 해결: 표 구조를 직접 읽는 `fieldsFromTables`. 기존 테스트의 "표 머리줄을 주요 업무로 잘못 넣지 않음(undefined)" 기대값은 이제 올바른 값을 채우므로 실제 값 확인으로 바꿨다.
4. **세션 사용량 한도로 작업 중단** — 같은 날 앞선 작업(본문 창·숨김 글·잡코리아 처리)이 전체 테스트 도중 멈춰 사용자 PC에 저장되지 않았다. 이번에 이어서 마무리하고 함께 저장했다.

### 검증
- TypeScript(화면·서버)·ESLint·Prettier PASS, `npm run build` PASS.
- 서버 테스트 11/11 PASS.
- 전체 Playwright 46/51 (작업 공간 Chromium 141, `PW_CHROMIUM` 지정). 실패 5개: `Math.sumPrecise` 2개·한글 다운로드 파일 이름 2개(기존과 같은 원인, 앱 코드 문제 아님), 다리 위 담이 움직임 프레임 확인 1개(`app.spec.ts:704`, 2번 반복 중 1번 통과 — 느린 작업 환경의 애니메이션 시점 차이로 보이며 이번 변경과 무관한 화면, 조사 중).
- **미실행**: 서버(Render 또는 사용자 PC)에서 채용 사이트로 직접 요청했을 때 사이트가 막는지 여부. 브라우저로 받은 HTML과 서버가 받는 HTML이 다를 수 있으므로 사용자 PC에서 `npm run check:job` 확인 필요.

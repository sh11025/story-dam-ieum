# Story Dam Ieum 개발 기록

## 현재 개발 상태

- 현재 작업: 사용자 사이트(Render, 이 폴더)와 관리자 화면(깃허브 페이지, admin-app)으로 분리 완료 (2026-10-14).
- 상태: 서버는 Node(Hono) 하나로 공지 읽기·공고 주소 가져오기·AI 요청 전달만 한다. 공지는 관리자 저장소의 `data/notices.json`. 문의·사이트 내 관리자·Cloudflare·Supabase는 제거했다.
- 제품 범위: 취업 작업은 `story-dam-ieum-draft-v1`과 `.sdi formatVersion: 1`으로 브라우저/사용자 기기에만 유지한다. 개인 AI key는 탭 메모리에만 둔다.
- 최근 검증(2026-10-15): 실제 공고 9개(사람인·원티드·잡코리아 각 3개)를 앱 안 브라우저로 받아 시험 — 글로 된 공고 6개 모두 5개 항목, 그림 공고 3개는 안내 표시. 사용자 PC `npm run check:job`으로 서버 방식 직접 요청도 같은 결과(차단 없음) 확인. TypeScript·ESLint·build PASS, 서버 테스트 11/11, 전체 Playwright 46/51(실패 5개는 작업 환경 시험용 브라우저 문제 4개 + 애니메이션 시점 1개, 조사 중), 관리자 4/4.
- 배포(2026-10-15): Render `story-dam-ieum.onrender.com` 동작·공지 연결·공고 가져오기 확인. 관리자 화면 원격 확인은 미실행.
- 흐름 변경(2026-10-15): 자기소개서·면접은 지원 정보부터 시작, '내 경험'은 자기소개서 쓰기 화면으로 합침, 경험↔이력서(프로젝트·활동/경력) 자동 연결. 사용자 PC `npm test` 57/57 통과(작업 공간에서만 실패하던 5개는 작업 공간 브라우저 문제로 확인).
- AI 모델(2026-10-15): AI 설정 창에서 회사별 3단계 모델 선택 + 직접 입력. 목록은 `shared/aiModels.ts`.
- Blocker: 없음. 다음 작업: 이번 변경 PC `npm test` 후 깃허브에 올리기, 실제 AI 키로 모델 호출 확인, 관리자 화면에서 공지 저장 후 사용자 화면 반영 확인, 휴대폰 폭 홈 카드 배치 개선.
- 참고: 2026-10-11 이전 기록의 일부 링크(backend 문서, artifacts, work, supabase 폴더)는 정리 전 폴더 기준이며, 사용자가 보관한 백업 압축파일에 있다.

## DEV_LOG 운영 규칙

- 사용자 시간대 Asia/Seoul, 월요일 00:00~일요일 23:59의 한 주를 한 파일로 관리한다.
- 작업 시작 때 날짜와 주간 파일을 확인하고, 없으면 새 파일을 만든 뒤 이 표에 등록한다.
- 작업·의미 있는 오류가 발생할 때마다 실제 확인한 사실을 추가한다. 완료 시 검증 상태를 갱신한다.
- 오류·Root Cause·해결 과정·실패한 시도를 보존한다. 과거 기록의 사실 오류는 정정 이유를 적는다.
- 구현과 검증, 로컬 실행과 원격 배포를 구분한다. 미실행 검증은 미실행으로 적는다.
- 비밀정보는 기록하지 않는다. 참고 자료의 프로젝트 고유 내용은 가져오지 않는다.
- 일일 기록은 추가/변경 기능, 오류, 원인, 해결, 검증, 상태, PPT용 한 줄 요약 순서로 작성한다.
- UI 또는 시각 레이아웃 변경은 실제 브라우저 검증과 캡처를 함께 수행한다. 캡처는 `test-results/`에 만들고 프로젝트 폴더에 쌓아 두지 않는다.

# Story Dam Ieum · 스토리 담 이음 (사용자 사이트)

자기소개서·이력서·면접 준비를 담이와 함께하는 웹사이트입니다. 이 폴더는 **사용자가 쓰는 사이트**이고, Render에 올립니다.
공지를 쓰는 **관리자 화면은 별도 폴더(admin-app)** 로 나뉘어 깃허브 페이지에 올립니다.

```
관리자 화면 (깃허브 페이지)  ──저장──▶  관리자 저장소의 data/notices.json
                                                  │
사용자 사이트 (Render)  ◀──공지 읽기(NOTICES_URL)──┘
```

## 무엇이 들어 있나요

| 주소 | 화면 |
| --- | --- |
| `/login` | 시작 화면 (회원가입 없음) |
| `/home` | 자기소개서·이력서·면접 시작, 저장한 작업 파일(.sdi) 불러오기 |
| `/application` | 채용공고 **붙여넣기 / 주소(URL)로 가져오기 / 파일(TXT·워드·PDF) 읽기**, 지원 정보 정리 |
| `/experience` | 내 경험 정리 |
| `/cover-letter` | 자기소개서 작성 |
| `/resume` | 이력서 작성 (기본형·신입형·경력형) |
| `/interview` | 면접 연습 |
| `/review` | 최종 점검, 워드·PDF로 저장 |
| `/notices` | 공지사항 (관리자가 깃허브에 저장한 공지) |

- 작성한 내용은 **사용자 브라우저에만** 저장되고 서버로 보내지 않습니다. 오래 보관하려면 `.sdi` 파일로 내려받습니다.
- 서버는 세 가지 일만 합니다. 공지 파일 읽어 오기, 공고 주소의 페이지 대신 받아 오기, AI 요청 대신 전달하기. 아무것도 저장하지 않습니다.

## 내 컴퓨터에서 실행하기

Node.js 22.12 이상이 필요합니다.

```powershell
npm install
npm run dev
```

브라우저에서 http://127.0.0.1:5173 을 열면 됩니다. 공지를 보려면 `.env.example`을 복사해 `.env`를 만들고 `NOTICES_URL`을 채우세요(없으면 "게시된 공지가 없습니다"로 나옵니다).

## Render에 올리기

1. 이 폴더를 깃허브 저장소(예: `story-dam-ieum`)로 올립니다.
2. Render → **New** → **Blueprint** → 그 저장소를 고르면 `render.yaml`대로 서버가 만들어집니다.
   (직접 만들 때: New → Web Service, Build Command `npm ci --include=dev && npm run build`, Start Command `npm start`)
3. Render의 **Environment**에 값을 넣습니다.
   - `NOTICES_URL`: 관리자 화면 아래 "사용자 사이트 연결"에 나오는 주소
   - `AI_OPENAI_MODEL` 등: AI 첨삭을 쓸 때만 모델 이름 입력(선택)
4. 배포가 끝나면 `https://(이름).onrender.com` 으로 접속합니다.

참고: Render 무료 요금제는 15분 동안 접속이 없으면 잠들어서, 다음 첫 접속이 1분 정도 걸릴 수 있습니다.

## 공고 주소로 가져오기

- 공고 페이지에 검색엔진용 정보(JobPosting)가 있으면 회사명·직무·주요 업무·자격요건을 바로 채웁니다.
- 없으면 페이지 글에서 `주요업무`, `자격요건`, `우대사항` 같은 제목을 찾아 그 아래 목록을 가져옵니다.
- 사이트가 막아 두었거나 공고가 그림이면 가져오지 못합니다. 이때는 붙여넣기를 안내합니다.
- 안전장치: http/https 주소만 허용, 내부망·자기 자신 주소 차단, 최대 3MB·10초, 우리 화면에서 온 요청만 허용, 같은 사람이 10분에 20번까지.

  pages/              화면별 파일 (Login, Home, Application, … , Notices)

  styles/             디자인 (base.css 기본, concept.css 컨셉 디자인)

## 정리 내역 (2026-10-14)

- Cloudflare·Supabase 서버 코드, 문의 기능, 사이트 안 관리자 화면을 없앴습니다. 공지는 깃허브의 `notices.json`으로 바꿨습니다.
- 한 파일에 몰려 있던 화면(`pages.tsx`, 1,776줄)과 부품(`components.tsx`, 818줄)을 화면·부품별 파일로 나눴습니다.
- 쓰지 않게 된 디자인 규칙(관리자·문의 화면용) 약 400줄을 지웠습니다.
- 테스트 캡처, 백업 압축파일, 담이 원본 작업 파일(`assets/dami/source`, 약 70MB)은 이 폴더에서 뺐습니다. 원본이 필요하면 백업해 둔 압축파일에서 꺼내 쓰세요.

## 2차 정리 (2026-10-14)

- 안 쓰는 코드 삭제: 쓰이지 않던 함수(`clearAiSession`, `fieldsToText` 등), 설정한 적 없는 `VITE_AI_PROXY_ENABLED` 스위치, 쓰이지 않던 디자인 규칙 34개.
- 중복 정리: 작업 종류별 이름·주소 계산(4곳 → `model.ts` 한 곳), 탭 버튼 줄(`Tabs` 부품), 수정안 비교 준비(자기소개서), 다른 작업 정보 모으기(이력서·면접), 서버 JSON 도우미.
- 오류 수정: AI "연결 확인" 성공 메시지가 빨간 오류 상자로 보이던 문제, AI 키를 넣어도 AI 기능이 꺼진 것처럼 보이던 문제, AI가 실패하면 면접 추가 질문이 아예 안 들어가던 문제(기본 연습 질문으로 대신), 요청 횟수 제한을 접속 주소 꾸미기로 피할 수 있던 문제.
- AI 설정 창을 `components/AiSettings.tsx`로 분리해, 창을 닫았다 열어도 입력 값이 유지되게 했습니다(브라우저에 저장하지는 않음).

## 추가 기능 (2026-10-15)

- **지원서 여러 개**: 홈의 "내 지원서"에서 회사별 지원서를 만들고 바꿔요. 새로 만들 때 경험·이력서를 복사할 수 있어요. 작업 화면 머리글의 선택 상자로도 바꿀 수 있어요.
- **모든 지원서 백업**: 지원서 전체를 `.sdi` 파일 하나로 저장·불러오기. 예전 지원서 1개짜리 `.sdi`도 그대로 열리고, 새 지원서로 추가돼요.
- **백업 알림**: 저장하지 않은 변경이 30분 넘으면 화면 오른쪽 아래에 알림. 10분 넘게 저장 안 한 채로 창을 닫으면 한 번 더 확인해요.
- **글자 수 세는 방법**: 문항마다 공백 포함 / 공백 제외 / 바이트(한글 2, 영문·숫자·공백 1, 줄바꿈 2).
- **마감일 D-day**: 공고에서 마감일을 찾아 채우고, 머리글과 내 지원서 목록에 D-day를 보여 줘요.
- **새 공지 표시**: 안 읽은 공지가 있으면 종 모양에 빨간 점. 공지는 `**굵게**`와 링크를 지원해요. 자주 묻는 질문도 관리자 화면에서 바꿀 수 있어요.
- **공고 가져오기 개선**: "Our Job", "이런 분을 찾고 있어요" 같은 제목, 화면 속 숨은 데이터(Next.js), 자격요건 안의 "(우대)" 줄까지 읽어요. 우리 서버가 못 가져오면 **AI로 다시 시도** 버튼으로 사용자의 AI 키를 써서 AI가 페이지를 직접 읽어요. 5초 넘게 걸리면 "서버를 깨우고 있어요" 안내가 나와요.
- **담이 이미지 가볍게**: 모든 담이 이미지를 화질 손실 없는 WebP로 바꿔 약 38% 줄였어요(6.6MB → 4.1MB).

### 공고 주소 시험 도구

실제 채용 사이트에서 공고를 가져올 수 있는지 내 컴퓨터에서 확인해요.

```powershell
npm run check:job -- https://www.saramin.co.kr/... https://www.wanted.co.kr/wd/...
npm run check:job -- urls.txt     # 한 줄에 주소 하나씩 적은 파일
```

결과는 화면과 `test-results/job-check.md`에 저장돼요. 이 파일을 보여 주시면 사이트별 맞춤 처리를 할 수 있어요.

### Render 설정 추가 안내

- AI로 공고 읽기는 서버의 AI 모델 이름(`AI_OPENAI_MODEL`, `AI_GEMINI_MODEL`, `AI_CLAUDE_MODEL`)이 설정된 AI만 쓸 수 있어요. 공고 읽기에는 웹 페이지를 읽을 수 있는 모델을 넣어 주세요(Gemini 2.5 이후, Claude 최신 모델 등).
- **서버 깨워 두기(선택)**: Render 무료 서버는 15분 동안 접속이 없으면 잠들어요. UptimeRobot 같은 무료 감시 서비스에 `https://(주소)/api/health`를 10분마다 확인하도록 등록하면 잠들지 않아요. 다만 무료 사용 시간(월 750시간) 안에서 쓰는 것이니, 서버를 하나만 쓸 때 권장해요.
